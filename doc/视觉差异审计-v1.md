# 文常记小程序视觉差异审计 v1

更新时间：2026-10-16
审计范围：16 个 HTML 原型、9 个原生小程序路由，以及 375/390/430 三档当前 QA 屏幕复制报告。
审计结论：**未完成逐像素 1:1 验收，不能标记 16 个状态视觉通过。** 当前页面结构和主要色彩已对应原型，但仍有数据差异、运行环境差异以及若干需要人工确认的布局差异。

## 判断方法与限制

本审计对照了原型 HTML 的布局声明、颜色声明、文本结构与小程序 WXML/WXSS，并查看代表性截图。原型是浏览器页面，小程序是微信渲染器；两者的字体回退、设备像素比、状态栏/胶囊和安全区不相同。原型浏览器样图在 375/390 宽度下还出现了 430px 内容容器的居中裁切，而小程序截图使用微信视口铺满页面。因此本轮没有把浏览器图片直接做像素相减，也没有把结构相似误报为逐像素一致。

## 分级问题

### 高优先级（交付前必须处理或明确豁免）

1. **逐像素验收未关闭（布局/环境）**：自动差异报告已覆盖 390×844 的 16 个配对，但数据、字体、微信渲染器和系统安全区差异仍会影响像素变化比例；需要同一数据快照下的人工标注和 375/390/430 三档复核后才能关闭。
2. **资料群正式二维码和口令未配置（数据/内容）**：当前页面正确显示缺失配置空态；接入正式环境前必须提供真实接口配置并重新截图，不能把占位框标为完成。

### 中优先级（联调或视觉收尾需记录）

1. **收藏示例数据不一致（数据）**：原型 6 条/今日新增 2，QA 3 条/今日新增 0；服务端未提供 `todayAdded`，应由产品确认展示“--/0/隐藏”中的一种，不应从本地 mock 补数。
2. **会员态不一致（数据）**：原型为未开通，QA 会话为已激活。需要分别留存未登录、无权益、已激活三张基准图，不能用已激活截图覆盖默认原型态。
3. **题目、篇目和轮次数据不一致（数据）**：文学、字词、翻译、随机和文言目录均按后端实际返回，原型为固定示例。应保留 QA fixture 快照，避免把题目变化误判为布局回归。
4. **窄屏长文本换行（布局/数据耦合）**：题干、答案、应用文正文和资料群口令长度会改变卡片高度、首屏可见数量和滚动位置；需在 375 宽逐一检查最长题干和最长口令。
5. **底部导航和安全区（布局/环境）**：原型使用浏览器固定 64px 导航，小程序使用 `env(safe-area-inset-bottom)`；在开发者工具和真机的高度、刘海、手势区不同，需以真机截图确认。

### 低优先级（可在视觉收尾统一）

1. **系统字体和抗锯齿差异（环境）**：HTML 使用浏览器字体回退，小程序使用微信字体渲染；文字边缘、字宽和行高会有像素级差异。
2. **图标载体差异（布局/环境）**：原型和小程序均使用字符/轻量图形，系统字体不同会造成图标宽度和基线轻微变化。
3. **页面状态附加控件（布局）**：小程序登录错误、远端来源提示、重试按钮、订单/详情弹层是联调所需状态，原型静态首屏没有对应控件；应在验收记录中按状态单独截图，不与默认态直接做像素比较。
4. **版本/QA 文案（数据）**：页脚、QA 题目标识、资料群“当前不是可扫码二维码”等文本属于测试配置，不应作为视觉回归的颜色或间距问题。

## 结论与后续门槛

当前可以确认：16 个原型状态都有真实小程序入口，修正前的 375/390/430 三档均生成 16/16 路由报告，390 修正后收藏页已单独复核，主要页面骨架、颜色体系、卡片和底部导航方向与原型一致。当前不能确认：逐像素 1:1、修正后 375/430 全量截图、一致的默认数据状态、真机安全区效果和正式资料二维码状态。

关闭本审计前需完成：

1. 以固定 QA fixture 重新采集 16 状态的默认/有数据/空态截图，并按 375、390、430 标注首屏、卡片边界、导航和文字换行差异。
2. 补齐资料群正式配置，或在交付记录中明确将其列为未完成项。
3. 通过 Android/iPhone 真机检查安全区、滚动和返回后，再更新高/中优先级项。
4. 仅当每个状态都有人工对照记录和修复后的截图，才可将“逐像素视觉验收”改为通过。
