# 应用文批量导入规范 v1

**Author:** Codex
**Date:** 2026-10-20（Asia/Shanghai）
**Status:** Draft — 规范已制定，导入功能尚未实施
**Reviewers:** 项目负责人、应用文内容运营、后端开发

## Context — 当前情况与目标

2026-10-20 已通过 SSH 只读核对线上 `/srv/chinese-study/current/backend/writing/`，并与本地最新代码比较。当前应用文后台支持分类、文种、逐条新增和编辑、预览、批量发布及下架；没有应用文上传导入页面、导入处理器或管理命令。`WritingContentAdmin.get_urls()` 只增加预览路由，批量操作只有发布和下架。导航中的“题库导入”属于 `content.Question`，不能导入应用文；`prepare_qa_fixture.py` 仅生成固定 QA 样例，不是业务导入工具。

现有入口：[内容管理 → 应用文内容](https://zsbzy.com/admin/writing/writingcontent/)。本文中“批量导入”“模板下载”等均为待实现能力，不能据此认为后台已提供这些按钮。

目标是让运营按统一 Excel 模板整理应用文，经过预览、整批校验和确认后保存为草稿，再使用现有发布流程上线。格式必须对应现有 `WritingContent`、`WritingCategory`、`WritingGenre` 模型；不直接写入发布修订，不改变学员接口和权益规则。

## Functional Requirements — 功能要求

- FR-1: 系统 MUST 仅接收 `.xlsx` 工作簿，使用本文规定的工作表、表头和数量限制；解析实际文件内容，不能仅凭扩展名接受文件。
- FR-2: 系统 MUST 校验稳定编号、文本长度、内容类型、必填项、参考答案条件及整数排序；文件内重复编号整批报错，即使重复行内容相同。
- FR-3: 系统 MUST 按编号关联分类和文种；引用必须已存在且启用，或在本次字典表中合法新增。不得按相近名称猜测关联，不得通过导入修改已有字典。
- FR-4: 系统 MUST 提供“仅新增”和“新增及更新草稿”两个明确模式。已有编号且规范化后字段完全相同的一律标记“未变化”；仅新增模式中同编号不同内容报错；更新模式中同编号不同内容覆盖可编辑草稿字段。文件遗漏的记录保持原状，不执行删除、停用或下架。
- FR-5: 系统 MUST 先生成只读预览，显示新增、修改、未变化、错误的数量及逐行差异；有任何错误时禁用确认导入；预览不写业务数据。
- FR-6: 确认导入 MUST 绑定当前操作人、文件 SHA-256、导入模式、规范化后的计划及依赖数据指纹，有效期 30 分钟。提交时重新验证权限并锁定相关数据；内容、发布状态、分类、文种或目标编号占用发生变化时整批拒绝，要求重新预览。所有业务写入及审计在同一数据库事务中完成。
- FR-7: 导入 MUST 只创建或更新草稿。新增内容的 `is_published=false`、`published_revision=null`；更新已发布内容时保留其发布状态、当前发布修订及全部历史。导入不得让新正文立即替换小程序正在展示的版本。
- FR-8: 系统 MUST 在入口、上传预览、确认和报告下载各阶段检查后台登录及权限。创建内容要求查看和新增应用文权限；更新已有内容额外要求修改应用文权限；创建字典额外要求对应查看及新增权限；发布权限只由原发布流程检查。代理本人及纯查看账号不具有导入操作权限。
- FR-9: 系统 MUST 记录操作者、批次 UUID、时间、模式、文件摘要、结果数量及变更编号。原文件与错误报告存放在非公开临时目录，绑定操作人；日志不复制正文、会话信息或密钥。确认请求重放不得重复创建或覆盖数据。
- FR-10: 后台 MUST 在应用文列表顶部提供“下载模板”“批量导入”入口，并在内容管理分组提供“应用文导入”入口；成功后提供本批内容列表及预览链接；错误报告包含工作表、Excel 原始行号、列名、错误码和中文修改建议。
- FR-11: 导入完成后 MUST 提供“查看本批草稿”入口；发布继续使用原有独立权限、签名确认、版本冲突校验和 `publish_writings()`。批量导入不自动发布。
- FR-12: 系统 MUST 保留正文和参考答案的有效换行及缩进，按纯文本展示；导入预览说明现有排序和免费集合规则，不提供逐篇“是否免费”或价格字段。

### Excel 工作簿结构

| 工作表名 | 是否必须 | 用途 |
| --- | --- | --- |
| 应用文 | 是 | 每行一篇独立内容，最多 1,000 条非空数据行 |
| 分类 | 否 | 需要一并新增的分类，最多 200 条 |
| 文种 | 否 | 需要一并新增的文种，最多 200 条 |
| 填写说明 | 否 | 模板填写指南，不参与业务解析 |

数据表第一行为表头，第二行开始为数据。表头顺序允许调整，列名必须精确匹配，所有规定列都必须存在；非必填指单元格可以留空。缺失、重复或未知表头报错，不能导入未声明字段。允许缺少可选工作表，不允许未知或隐藏工作表。数据表不允许隐藏行列、合并单元格、图片、公式、错误单元格、外部链接、宏、加密和密码保护；空行忽略并保留原始 Excel 行号供报错使用。填写说明只能包含填写说明，不能携带业务数据或公式等主动内容。

### “应用文”字段规范

| Excel 列名 | 必填 | 后端字段 | 规则及示例 |
| --- | --- | --- | --- |
| 内容编号 | 是 | `id` | 1～64 位，仅 `A-Z a-z 0-9 _ -`；如 `notice-template-001`；全局唯一且保存后不能改 |
| 分类编号 | 是 | `category_id` | 1～64 位合法编号；引用分类表，如 `daily-writing` |
| 文种编号 | 否 | `genre_id` | 留空表示不指定文种；填写时引用启用文种，如 `notice` |
| 内容类型 | 是 | `kind` | 四个中文名称或对应英文代码，映射见下表 |
| 标题 | 是 | `title` | 去掉首尾空白后 1～200 字符，如 `通知的写作格式` |
| 正文 | 是 | `body` | 不能只有空白；本导入格式上限 20,000 字符；专项练习填题目，其余填模板、范文或真题完整文本 |
| 参考答案 | 条件必填 | `reference_answer` | 仅专项练习必须填写，最多 20,000 字符；其他三种类型必须留空 |
| 排序 | 否 | `sort_order` | 0～2,147,483,647 的整数，留空默认 0；越小越靠前，相同时按内容编号排序 |

这里的正文及答案长度上限是导入规范新增的限制，现有后端 `TextField` 没有该长度限制。编号列应设置为“文本”，数字类型的编号报错，防止 Excel 丢失前导零；不会自动补编号或改写编号大小写。只去掉编号、内容类型和标题的首尾空白；正文及答案仅把 CRLF/CR 规范化为 LF，保留缩进、空行和段落。可空文本的空白单元格归一为空字符串。

更新模式是完整草稿替换：文种留空会清除原文种，排序留空会置 0；其余字段遵守必填条件。预览必须突出显示这些变更。文本单元格里的 `1` 不是合法排序数值，排序列使用真正的整数；布尔值、小数、日期、负数、科学计数文本均报错。

| 内容类型填写值 | 接受的英文代码 | 参考答案填写规则 |
| --- | --- | --- |
| 写作模板 | `template` | 留空；模板正文放在“正文” |
| 范文示例 | `example` | 留空；范文全文放在“正文” |
| 历年真题 | `past_exam` | 留空；需要展示的材料、题干、解析和答案按段落写入“正文” |
| 专项练习 | `exercise` | 必填；题目放“正文”，答案放“参考答案” |

“分类”是内容归属；“文种”是通知、请假条、倡议书、申请书等写作体裁；“内容类型”决定小程序进入四个模块中的哪一个。三者分别填写，不能把“通知”当内容类型。

### “分类”“文种”字段规范

| 工作表 | 固定列名 | 规则 |
| --- | --- | --- |
| 分类 | 分类编号、分类名称、排序 | 编号 1～64 位且符合编号规则；名称去首尾空白后 1～120 字符；排序同内容排序规则 |
| 文种 | 文种编号、文种名称、排序 | 编号 1～64 位且符合编号规则；名称去首尾空白后 1～120 字符；排序同内容排序规则 |

新增字典项默认启用，预览显示其新增数量。与数据库同编号同名称同排序则复用；同编号不同名称或排序则报错，要求先在字典管理页单独修改。已停用字典不能通过导入重新启用。不同编号却同名的新增项报错，提示复用已有编号，避免重复分类。没有引用的新增字典行也报错，要求删除该行或补齐应用文引用，防止误建空分类。

## Non-Functional Requirements — 非功能要求

- NFR-1: MUST 限制上传大小为 5 MiB、ZIP 解压总大小为 50 MiB、ZIP 成员最多 2,000 个；流式解析最多 1,000 条内容及各 200 条字典数据。超限在业务写入前明确拒绝，不允许通过切换后缀绕过。
- NFR-2: MUST 使用 HTTPS、后台会话和 CSRF；上传文件使用服务端随机名存入私有目录，文件名不得决定路径；临时文件不通过 `/media/` 暴露。过期预览不能提交，临时文件及报告最迟 24 小时内清理，审计日志保留。
- NFR-3: MUST 确保任一校验、权限、数据库写入或审计失败后，本批业务数据全部回滚；并发提交最多产生一次有效写入结果。若提交成功但响应丢失，页面提示核对批次结果，不得宣称失败后自动重复覆盖。
- NFR-4: SHOULD 在 2 vCPU、2 GiB、同机 PostgreSQL 环境中，对 1,000 行、每行正文 500 字符、答案平均 100 字符的样本，在 10 秒内完成预览；实施时实测并记录性能，当前未执行此基准测试。
- NFR-5: MUST 全中文显示入口、结果、空态和错误；上传失败、预览过期、权限不足及版本冲突均给出可操作提示。错误报告导出单元格须强制文本类型，不能把输入重新变为 Excel 公式。

## Acceptance Criteria — 验收标准

### AC-1: 文件格式与字段校验 (FR-1, FR-2; NFR-1, NFR-5)

Given 合法工作簿及分别含缺列、未知列、错误类型、超长标题、重复编号、公式、合并单元格和超限数据的工作簿；When 上传预览；Then 合法文件展示全部行，其余文件按原行号返回中文原因，确认按钮不可用，数据库无变化。

### AC-2: 分类文种关联 (FR-3)

Given 已启用、已停用、新增、同名异编号及同编号不同名称的字典；When 预览并确认；Then 只复用完全一致的启用项或新增合法引用项，错误引用和不一致项整批拒绝，不产生重复或空字典。

### AC-3: 新增更新与重复导入 (FR-4, FR-9; NFR-3)

Given 包含新增、原样已有、已修改已有内容的文件；When 分别选择两种模式并重复提交；Then 仅新增拒绝已有不同内容，更新模式展示逐字段变更，未变化数据不重写，重复提交不再变更数据，不处理文件外记录。

### AC-4: 预览有效性与事务 (FR-5, FR-6; NFR-2, NFR-3)

Given 一份无错误预览；When 文件计划被篡改、超过 30 分钟、换账号、预览后他人修改依赖或写入中途失败；Then 确认整批拒绝或回滚，不残留分类、草稿及成功审计。相同新编号的并发预览只允许一个有效新增事务，另一请求明确冲突。

### AC-5: 发布版本隔离 (FR-7, FR-11)

Given 一篇已发布内容和一篇新增内容；When 导入更新草稿但尚未发布；Then 小程序继续显示旧发布版，新增草稿不可见；再次按现有确认流程发布后，才生成相应发布修订并展示新内容。

### AC-6: 权限、入口与审计 (FR-8, FR-9, FR-10; NFR-2, NFR-5)

Given 应用文编辑、应用文发布、纯查看、代理本人及未登录账号；When 打开导入入口、直接访问 URL、确认或下载他人报告；Then 各阶段按实际所需权限允许或拒绝，越权请求不返回原文件或报告；成功批次具有可核对的审计和本批内容入口。

### AC-7: 四种类型与纯文本保真 (FR-2, FR-12)

Given 四种类型样例及含缩进、多段、中文标点的正文；When 导入、预览、发布并在小程序打开；Then 类型归属正确、正文完整、换行与缩进保留；只有专项练习有独立参考答案，HTML 形似文本不被执行或当作富文本渲染。

### AC-8: 小程序可见性与免费集合 (FR-11, FR-12)

Given 同一分类已发布数量超过 `LearningConfiguration.page_size`，覆盖四种类型，并分别使用未开通和已开通权益账号；When 按类型、分类、分页读取列表和详情；Then 结果符合现有共享免费集合和永久权益策略；停用字典或下架内容不显示；收费详情无权益时不泄漏正文及答案。

### AC-9: 限制与性能 (FR-1, FR-5; NFR-1, NFR-4)

Given 边界大小、压缩炸弹样式和标准 1,000 行样本；When 进行上传及预览；Then 超限文件被及时拒绝，标准样本按规定环境记录耗时并达到性能目标；资源超限不返回部分导入成功。

## Edge Cases — 异常与边界

- EC-1: 文件扩展名伪装、损坏、加密、恶意 ZIP、公式、Excel 错误值、宏或外链：拒绝文件，不执行计算或访问外部地址。
- EC-2: Excel 将编号转为数字或科学计数：报错并提示编号列设为文本后重新填写，不猜测原编号；编号大小写不同视为不同编号。
- EC-3: 日期、布尔值、小数、负数填在排序列：报错；`0` 是有效值，不按空值处理。
- EC-4: 单元格中真的写了 `\n` 或 `↵`：保持为普通字符，不自动换行；预览提示使用 Alt+Enter。真实换行按 LF 规范化。
- EC-5: 已发布内容导入新草稿：发布版不变，后台显示有未发布修改；不直接覆盖 `WritingRevision`。
- EC-6: 预览后被修改、被发布、被下架、字典停用或新编号被占用：确认失败并提示重新预览；禁止静默采用最新数据继续写入。
- EC-7: 双击确认、两个窗口确认同批次、网关超时后重试：不得二次覆盖。已有成功批次返回已完成摘要；提交结果未知时引导按批次核对，不能直接宣称成功或重新执行。
- EC-8: 临时存储不可写、文件提前清理、磁盘满、数据库不可用或审计失败：给出中文错误，无半批业务数据；不调用微信、支付或权益写入。
- EC-9: 预览与提交之间撤销操作人权限或禁用账号：重新校验并拒绝。
- EC-10: 更新内容类型时原答案不符合新类型：整批报错，要求明确清空或补全参考答案；不静默丢弃答案。
- EC-11: 导入成功后小程序仍为空：按“是否发布 → 发布分类/文种是否启用 → 类型是否正确 → 当前账号权益及免费集合 → 当前 API 环境”依次检查，不以导入成功替代展示验收。

## API Contracts — 后台内部契约（拟议）

不增加小程序公开接口。以下均使用 Django Admin 会话、CSRF 及权限校验，返回 HTML 页面或附件，接口名称和上下文结构是实施约定，当前不存在这些路由。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /admin/writing/writingcontent/import/` | 展示上传、导入模式和填写说明 |
| `POST /admin/writing/writingcontent/import/` | multipart 提交 `import_file`、`mode`，返回只读预览及确认凭证 |
| `POST /admin/writing/writingcontent/import/confirm/` | 提交预览编号及签名凭证，整批确认；成功后跳转结果页 |
| `GET /admin/writing/writingcontent/import/template/` | 下载带填写说明、类型说明及字典清单的标准模板；数据表默认留空，样例放说明页 |
| `GET /admin/writing/writingcontent/import/report/{previewId}/` | 下载仅本操作人有权访问的错误报告；使用服务端 UUID 映射私有存储 |

```typescript
type ImportMode = 'create_only' | 'upsert_draft';
interface ImportIssue {

  column: string | null;
  code: string;
  message: string; // 中文原因和修改建议
}
interface ImportPreviewContext {
  previewId: string;
  mode: ImportMode;
  counts: { create: number; update: number; unchanged: number; errors: number };
  dictionaries: { categoriesToCreate: number; genresToCreate: number };
  issues: ImportIssue[];
  canConfirm: boolean;
  confirmationToken: string | null; // 有错误时不签发
  expiresAt: string;
}
interface ImportResultContext {
  batchId: string;
  status: 'completed' | 'already_completed';
  counts: { created: number; updated: number; unchanged: number };
  contentIds: string[];
  published: false; // 表示本次导入没有执行发布，不代表已有内容全部下架
}
```

已通过登录及 CSRF 的请求：数据/文件错误返回 400 页面；权限不足返回 403；报告或预览不存在返回 404；版本冲突/重复执行中返回 409；预览过期返回 410；服务故障返回 503。未登录沿用后台登录重定向，不在错误中暴露服务器路径或堆栈。

建议错误码包括 `INVALID_WORKBOOK`、`INVALID_HEADER`、`INVALID_VALUE`、`REQUIRED_FIELD`、`DUPLICATE_ID`、`RELATED_NOT_FOUND`、`RELATED_DISABLED`、`EXISTING_CONTENT_CONFLICT`、`DICTIONARY_CONFLICT`、`PREVIEW_EXPIRED`、`PREVIEW_CONFLICT`、`IMPORT_UNAVAILABLE`。下载报告使用 XLSX 纯文本单元格，避免 CSV 公式歧义。

## Data Models — 与现有数据模型的对应

| 模型/对象 | 参与字段 | 约束及处理 |
| --- | --- | --- |
| `WritingCategory` | `id, name, sort_order, is_active` | 按编号复用或新增；新增启用；已有字典不批量修改 |
| `WritingGenre` | `id, name, sort_order, is_active` | 文种为可空引用；其他规则同分类 |
| `WritingContent` | `id, category, genre, kind, title, body, reference_answer, sort_order` | 仅可编辑草稿字段参与更新；锁定并保留发布相关字段 |
| `WritingRevision` | 现有发布快照及版本号 | 导入不创建、不修改、不删除；发布服务负责生成 |
| `LearningConfiguration` | `page_size` | 决定分类首屏共享免费集合；导入不能覆盖 |
| 预览计划（私有临时对象） | UUID、actor、摘要、mode、规范化计划、依赖指纹、到期时间 | 服务端存储，签名绑定，客户端不决定文件路径；不是新业务模型 |
| 确认结果（私有临时对象及后台审计） | 批次 UUID、最终状态、计数、变更编号 | PostgreSQL 事务级批次锁串行确认，事务内以批次审计为已完成标记；无变更批次同样记录。响应丢失或进程重启后先查已提交标记，不再次执行；临时对象清理后凭证失效 |

一期复用现有增改查权限和后台 `LogEntry`，不要求新增业务表或数据库字段。批次标记写入审计与业务修改同事务，并按 `batchId` 明确关联；若现有审计无法满足持久幂等或批次追溯，须在实施前修订设计，不以跨 worker 不共享的进程内锁替代。

### 发布后的小程序展示规则

1. 草稿导入成功 ≠ 小程序可见；内容必须走现有发布服务。
2. 发布修订引用的分类及非空文种必须启用；下架内容不展示。
3. 同一分类内按发布修订的排序及内容编号选取前 `page_size` 条免费内容，四种类型共用一个免费集合；按类型过滤不会新增免费名额。
4. 未开通账号只能读取免费集合；已开通永久权益账号可读取全部已发布且字典启用的应用文。
5. 当前模型没有年份、考试地区、独立解析、富文本或图片字段；所需的年份/地区写进标题，解析按段落写入正文，不增加未约定列。

## Out of Scope — 本期边界

- OS-1: Word/PDF/图片 OCR 和任意旧表自动猜列；先统一成本文 Excel 格式，避免自动猜错关联和内容类型。
