## 四、按优先级执行

### P0：DNS、TLS、Nginx

通过标准：两个域名的 A/AAAA 在权威 DNS、服务器、1.1.1.1、8.8.8.8 一致；不存在旧入口；`nginx -t` 通过；证书域名/有效期正确；`/healthz`、`/readyz` 和商品接口从服务器及外部网络结果一致；带正确签名的回调 GET 返回 200 和原样 `echostr`。

### P1：生产数据和 API

1. 生产数据库确认 `all-chinese`、平台编号 `VIP`、金额 10 分、发布状态。
2. `/api/student/v1/products/` 返回该商品，不得继续 `count=0`。
3. 分类、题目、文章、应用文、资料群接口至少返回可用数据或明确空态。
4. 在开发者工具扩展配置设置 `apiBaseUrl=https://zsbzy.com`；关闭 `urlCheck` 绕过，清缓存重编译，确认请求不再出现 `127.0.0.1:8000`。

### P2：真实登录与学习闭环

使用独立 QA 微信身份依次验证：`wx.login`、会话恢复、首页统计/续学、文学自测/背诵、查看答案、掌握、收藏/取消、我的收藏三种状态、字词/翻译练习、文常/文言随机轮次、下一组、保存和恢复、退出、401 单次刷新、断网重试、无效 code。

通过标准：服务端数据跨页和重启一致；写请求带 `baseVersion` 与幂等键；409 能按服务端版本恢复；403 不泄露题干/答案；失败不显示成功。

### P2：业务页

验证应用文分页/详情、我的权益/统计/订单详情、QA 激活码幂等兑换、反馈重复提交、资料群二维码/口令及缺配置空态。只使用 QA 数据。

### P3：支付

保持三个开关为 `false`。先验证兼容模式正确签名、错误签名、缺签名、未知订单、重复回调；只有 Android 沙箱完成下单、支付、回调、查单、发权后，才单独评审是否打开 Android 开关。iOS 0.1 元商品保持关闭。

### P3：视觉和真机

固定同一 QA 数据快照，在 375×667、390×844、430×932 重采集 16 状态；记录原型文件、入口参数、截图、差异等级和修复提交。Android/iPhone 分别检查登录、返回、安全区、滚动、HTTPS 和断网恢复。逐像素 1:1 只有人工标注和修复截图齐全后才能通过。

### P4：运维和发布

确认 PostgreSQL 迁移、备份/恢复演练、定时任务、防火墙只开放 22/80/443、8000 不公网开放、日志脱敏和回退目录。发布时使用 `/srv/chinese-study/releases/<commit>` 与 `current` 软链接。

## 五、服务器 Agent 核查命令

命令只输出状态和脱敏摘要，不输出密钥值：

```bash
set -Eeuo pipefail
BASE=/srv/chinese-study
APP="$BASE/current"
ENV=/etc/chinese-study/backend.env

echo '== DNS =='
getent ahostsv4 zsbzy.com || true
getent ahostsv4 www.zsbzy.com || true
getent ahosts zsbzy.com || true

echo '== VERSION/SERVICE =='
readlink -f "$APP"
test -f "$APP/backend/manage.py"
systemctl is-active chinese-study
systemctl status chinese-study --no-pager -n 40
nginx -t
ss -ltnp | grep -E ':(22|80|443|8000)([[:space:]]|$)' || true

echo '== ENV KEYS, VALUES HIDDEN =='
for key in DJANGO_SECRET_KEY STUDENT_SESSION_ENCRYPTION_KEYS WECHAT_APP_ID WECHAT_APP_SECRET VIRTUAL_PAYMENT_OFFER_ID VIRTUAL_PAYMENT_APP_KEY VIRTUAL_PAYMENT_SANDBOX_APP_KEY VIRTUAL_PAYMENT_CALLBACK_TOKEN VIRTUAL_PAYMENT_CALLBACK_AES_KEY; do
  if grep -Eq "^${key}=[^[:space:]]" "$ENV"; then echo "$key=SET"; else echo "$key=MISSING_OR_EMPTY"; fi
done
grep -E '^(DJANGO_DEBUG|DB_ENGINE|VIRTUAL_PAYMENT_ENABLED|VIRTUAL_PAYMENT_ANDROID_ENABLED|VIRTUAL_PAYMENT_IOS_ENABLED|VIRTUAL_PAYMENT_ENV)=' "$ENV"

echo '== HTTP =='
curl --fail --silent --show-error --max-time 15 https://zsbzy.com/healthz
curl --fail --silent --show-error --max-time 15 -H 'Host: zsbzy.com' http://127.0.0.1:8000/readyz
curl --fail --silent --show-error --max-time 15 https://zsbzy.com/api/student/v1/products/ | "$BASE/venv/bin/python" -c 'import json,sys; d=json.load(sys.stdin); print("product_count=",d.get("count"),"product_ids=",[x.get("id") for x in d.get("results",[])])'
echo

echo '== DATABASE COUNTS =='
set -a
. "$ENV"
set +a
"$BASE/venv/bin/python" "$APP/backend/manage.py" shell -c "from entitlements.models import Product; from content.models import Article, Category; from content.access import published_questions; from writing.access import published_writings; from resources.models import GroupResourceConfiguration; print('products=', list(Product.objects.values('id','price_fen','is_active','platform_product_id','platform_sync_state'))); print('active_categories=', Category.objects.filter(is_active=True).count()); print('active_articles=', Article.objects.filter(is_active=True).count()); print('published_questions=', published_questions().count()); print('published_writings=', published_writings().count()); c=GroupResourceConfiguration.current(); print('resources=', bool(c and c.is_enabled), 'qr=', bool(c and c.group_qr_code), 'claim_code=', bool(c and c.claim_code))"
```

如果 `current` 是归档发布目录，不要在其中执行 `git pull`；先校验新包 SHA-256，再创建新 release 目录，迁移和健康检查通过后切换软链接。
