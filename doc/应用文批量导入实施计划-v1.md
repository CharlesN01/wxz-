# 应用文批量导入实施计划 v1

日期：2026-10-20。基线：`ef2ec3e`；集成分支：`codex/writing-batch-import`。

实施依据为《应用文批量导入规范 v1》。本次新增后台 Excel 导入能力，复用应用文模型、编辑权限、发布服务和学员接口；不引入业务表或数据库迁移。

## 阶段与分工

| 阶段 | 工作 | 交付与通过条件 |
| --- | --- | --- |
| 1 | 固定模块边界及契约，建立隔离工作树 | 三个独立分支，明确文件所有权，规范状态更新 |
| 2 | 三个 Agent 并行实现 | 各自范围内测试及独立提交；不直接推送共享分支 |
| 3 | 主 Agent 审查集成 | 按文件处理、事务服务、后台页面顺序合并；解决契约差异 |
| 4 | 完整验证及验收 | SQLite 回归、PostgreSQL 并发、模板兼容、后台浏览器、部署检查及无迁移检查 |
| 5 | 版本交付 | 合并到原交付分支，推送远端；记录功能入口、检查结果及实际部署状态 |

### Agent A：工作簿与导入文件

文件边界：`backend/writing/import_files.py`、`backend/writing/tests/test_import_files.py`。

- 验证 XLSX/ZIP 结构与资源上限，拒绝隐藏、合并、公式、外链、图片、宏等不支持结构。
- 解析三种业务工作表；固定表头、准确行号、字段类型和长度、四种类型及参考答案条件。
- 保留正文换行及缩进，规范化值；空业务表返回明确错误。
- 生成下载模板和只含错误定位信息的 XLSX 报告，所有文本强制字符串。
- 测试真实已交付模板的兼容性，样例只放填写说明；不得误把说明解析成内容。

### Agent B：预览、事务、权限与存储

文件边界：`backend/writing/import_services.py`、`import_storage.py`、新增清理管理命令及服务测试、并发测试。

- 按编号验证字典与内容，生成新增/修改/未变化计划及逐字段差异。
- 私有临时文件、30 分钟签名确认、操作人绑定、依赖指纹与冲突校验。
- PostgreSQL 事务锁、已有行锁、唯一约束及批次审计实现全有或全无与重放保护；SQLite 使用测试配置的事务串行语义，不伪称 PostgreSQL 并发通过。
- 保留已发布快照；只改草稿；对预览后发布/下架/停用/编号占用失败关闭。
- 审计只记录批次、编号、摘要和计数；不记录正文。
- 提供独立过期文件清理命令，主 Agent 接入部署 timer，最长 24 小时清理。

### Agent C：后台工作流与页面

文件边界：`backend/writing/import_admin.py`、`admin.py`、应用文导入模板目录、`config/admin_navigation.py`、`operations/admin_dashboard.py`、后台导入测试及使用说明。

- 应用文列表顶部和内容管理侧栏增加导入及下载入口。
- 上传、模式选择、预览、中文错误、逐字段差异、签名确认、结果和本批列表入口。
- 各阶段权限、CSRF、错误状态码、报告下载隔离；已有发布操作保持原有确认流程。
- 页面不显示数据库技术字段、服务器路径或异常堆栈。

### 主 Agent：集成、验证和交付

- 负责规范、计划、配置、清理任务部署模板、跨模块集成、回归及浏览器验收。
- 先用隔离测试库验证导入→草稿不可见→发布→免费/权益可见性；不自动导入甲方生产数据。
- 检查原题库导入、应用文发布、后台权限和学员接口回归。
- 提交只包含本次代码和已交付模板，不提交 `.env`、临时原文件、数据库或已有压缩包。

## 共用模块契约

文件处理接口：

```python
parse_workbook(raw: bytes, filename: str) -> dict
# {contents: [{row: 2, values: {id, category_id, genre_id, kind, title,
# body, reference_answer, sort_order}}], categories: [{row, values: {id, name, sort_order}}],
# genres: [{row, values: {id, name, sort_order}}], issues: [{sheet,row,column,code,message}]}
make_template(categories=(), genres=()) -> bytes
make_error_report(issues) -> bytes
```

服务接口：

```python
has_import_permission(actor) -> bool
build_import_preview(parsed: dict, actor, mode: str) -> dict
confirm_import(preview: dict, actor) -> dict
# 预览含 counts/create/update/unchanged/errors、dictionaries、issues、rows、plan、
# dependencies、mode、canConfirm、owner；结果遵守规范 ImportResultContext。
```

存储接口：

```python
save_preview(actor, raw: bytes, preview: dict) -> dict
# 补齐 previewId、fileDigest、createdAt、expiresAt；无错误时签发 confirmationToken。
load_preview(preview_id: str, actor, token: str | None = None) -> dict
# token非None时严格验证签名、计划摘要、原文件摘要及操作人。
cleanup_expired_previews() -> int
```

所有可预期失败统一为 `WritingImportError`（定义在 `import_services.py`），带 `code`、`message`、`status`，供后台展示；解析器的内容错误统一放入 `issues`，不依赖后台 HTTP 层。

后台 URL 使用规范定义的 `/admin/writing/writingcontent/import/`、`confirm/`、`template/`、`report/{previewId}/`。页面接收字段固定为 `import_file`、`mode`、`preview_id`、`confirmation_token`。结果通过导入页的本批筛选链接查看，不新增小程序路由。

## 验收重点

1. 四种类型模板可填可解析，完整行号与字段错误报告，无写入预览。
2. 字典存在/新增/停用/同名冲突；新增与更新模式；完整草稿替换与未变化跳过。
3. 权限撤销、CSRF、跨账号报告、签名篡改、过期和文件损坏均失败关闭。
4. 双击确认、同编号并发、重复提交、响应丢失后重试不重复写入或覆盖。
5. 导入修改已发布内容仍展示旧修订；发布后显示新修订；权益规则不变。
6. 模板下载、预览、错误、确认、结果完成桌面后台显示检查。
7. 后端全量测试、`manage.py check`、`makemigrations --check --dry-run`、契约检查、`git diff --check`。

最终记录只标记实际执行通过的检查；生产部署及数据库环境结果与本机测试分别列明。
